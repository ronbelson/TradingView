## שינוי 2 (המשך מהנקודה שנחתכה)

### כלל v2 מוצע (המשך)
התאם את סף הרדיפה ל־**swingPct** של 4H:
- אם swingPct < 2% → סף רדיפה = **0.15%**
- אם swingPct 2–5% → סף = **0.25%**
- אם swingPct > 5% → סף = **0.4%**

**מספרים ברורים בקוד:**
```javascript
const swingPct = center.swingPct; // כאן 4.8%
let chaseThreshold;
if (swingPct < 2) chaseThreshold = 0.0015; // 0.15%
else if (swingPct <= 5) chaseThreshold = 0.0025; // 0.25%
else chaseThreshold = 0.004; // 0.4%

if (lean === 'long' && price > emaFast * (1 + chaseThreshold)) {
  lean = 'wait';
  headline = `לונג רק ליד ממוצע מהיר 4H ב־${emaFast.toFixed(2)}, לא לרדוף`;
}
```

### איך זה משנה את ההחלטה הנוכחית
- swingPct = **4.8%** → סף = **0.25%**
- המחיר **0.163%** מעל emaFast → **מתחת לסף החדש** (0.25%)
- אם הציון היה ≥1.2 (lean=long לפני דריסה):
  - **לא היה נדרס** → lean = long
  - **סטטוס = now** (המחיר קרוב מספיק לממוצע)
  - **ההחלטה משתנה** מ־wait ל־**פעולה מיידית**

**אבל**: כאן הציון 1.0 (< 1.2), אז lean=wait גם ב־v1 וגם ב־v2. **אין שינוי בפועל**.

### סיכון / תופעת לוואי
- בתנודתיות גבוהה (swingPct > 5%), סף 0.4% עלול **לאפשר רדיפה** יתר.
- בתנודתיות נמוכה, סף 0.15% עלול **להחמיץ** כניסות לגיטימיות.
- **פתרון**: להוסיף בדיקת ATR (Average True Range) בנוסף ל־swingPct.

**מספרים ברורים:**
```javascript
if (shortEntry.rr < 1.0) {

### איך זה משנה את ההחלטה הנוכחית

  ```
- **בchart**: עמודת "תפקיד שורט" ריקה או מסומנת "לא בר־ביצוע"

### סיכון / תופעת לוואי

## שינוי 4: העדפת פיבוט גדול על ממוצע באזור צפוף

### מה שבור ב־v1
- לונג בוחר **emaFast (64440.51)** כהכניסה, למרות ש־**railDn (64291.05)** קרוב יחסית ובעל העדפה גבוהה יותר (pref=2.2 מול 3.0).
- הסיבה: emaFast **מתחת** למחיר ב־0.16%, ו־railDn מתחת ב־0.39%.
- אבל **railDn הוא פיבוט גדול** (תמיכה מבנית), בעוד emaFast הוא **ממוצע דינמי** (פחות אמין).

### כלל v2 מוצע
כשמחליטים בין ממוצע (emaFast) לפיבוט גדול (railDn/railUp):
- אם המרחק בין שתי הרמות < **0.5%** (של המחיר) → **העדף את הפיבוט הגדול**
- אחרת: שמור על ההעדפה הרגילה (pref)

**מספרים ברורים:**
```javascript
const distEmaFast = Math.abs(price - emaFast) / price; // 0.0016 = 0.16%
const distRailDn = Math.abs(price - railDn) / price;   // 0.0039 = 0.39%
const gap = Math.abs(emaFast - railDn) / price;        // 0.0023 = 0.23%

if (gap < 0.005) { // 0.5%
  // שתי הרמות קרובות → העדף railDn (pref 2.2) על emaFast (pref 3.0)
  entry = railDn;
} else {
  // רחוק → העדף emaFast
  entry = emaFast;
}
```

### איך זה משנה את ההחלטה הנוכחית
- gap = |64440.51 − 64291.05| / 64545.36 = **149.46 / 64545.36 = 0.23%** < 0.5% ✓
- **כניסת לונג משתנה** ל־**64291.05** (railDn)
- **סטופ משתנה** ל־**63894.3** (pivotSmallDn)
- **risk חדש** = |64291.05 − 63894.3| / 64291.05 × 100 = **0.62%**
- **reward** (ל־64757.99) = |64757.99 − 64291.05| / 64291.05 × 100 = **0.73%**
- **rr חדש** = 0.73 / 0.62 = **1.17** (עדיין > 1.0 ✓)

**השפעה:**
- **כניסה נמוכה יותר** → סיכוי גבוה יותר למילוי
- **risk קטן יותר** (0.62% מול 0.23%) → **פוזיציה גדולה יותר** לאותו סיכון בדולרים
- **rr יורד מעט** (1.17 מול 2.12), אבל עדיין בר־ביצוע

### סיכון / תופעת לוואי
- אם railDn **נשבר** אבל emaFast **מחזיק** → ההחלטה ב־v2 תפעיל סטופ מוקדם מדי.
- **פתרון**: להוסיף תנאי: "אם המחיר כבר **מעל** railDn ב־> 0.2% → דלג על העדפת railDn".

## שינוי 5: תיקון 1H משוקלל (במקום דילוג)

### מה שבור בשינוי 1 שהצעתי
- **דילוג מוחלט** על תיקון 1H כשאין התאמה עם 4H → מתעלם מאותות מוקדמים.
- **שיקלול 0.2** במקום 0.4 (שהצעתי בסיכון) עדיין **שרירותי**.

### כלל v2 מוצע (טוב יותר)
במקום דילוג או הקטנה, **שקלל לפי כיוון 30m**:
- אם 1H **מסכים** עם 30m (שניהם bull או שניהם bear) → **+0.4 / −0.4 מלא**
- אם 1H **לא מסכים** עם 30m → **+0.2 / −0.2 חצי**
- אם אין נתוני 30m → חזור לכלל המקורי (±0.4)

**מספרים ברורים:**
```javascript
const tf1h = tfs.find(t => t.tf === '1H');
const tf30m = tfs.find(t => t.tf === '30m');

let weight1h = 0.4; // ברירת מחדל
if (tf30m) {
  const agree = (tf1h.stack === tf30m.stack) || (tf1h.channel === tf30m.channel);
  if (!agree) weight1h = 0.2; // חצי משקל
}

// החל על bub
if (tf1h.bub === 'HL' || tf1h.bub === 'LL') score += weight1h;
if (tf1h.bub === 'HH' || tf1h.bub === 'LH') score -= weight1h;

// החל על zap
if (tf1h.zap === 'GREEN') score += weight1h;
if (tf1h.zap === 'RED') score -= weight1h;
```

### איך זה משנה את ההחלטה הנוכחית
- 1H: stack=bear, channel=down
- 30m: stack=bull, channel=up
- **אין הסכמה** → weight1h = **0.2**
- ציון 1H:
  - bub LH → −0.2
  - zap GREEN → +0.2
  - **נטו = 0** (כמו ב־v1)
- **ציון סופי = 1.0** (ללא שינוי)

**אבל**: אם היה רק bub LH (בלי zap GREEN):
- v1: −0.4 → ציון 0.6
- v2: −0.2 → ציון 0.8 → **lean עדיין wait** (< 1.2), אבל **קרוב יותר ללונג**

### סיכון / תופעת לוואי
- **מורכבות**: 3 טיימפרמים (4H, 1H, 30m) → יותר תנאים לבדוק.
- **רעש**: 30m תנודתי → עלול לשנות משקל 1H בטעות.
- **פתרון**: להוסיף תנאי נוסף: "אם swingPct של 1H < 1% → התעלם מ־1H לגמרי" (רעש טהור).
